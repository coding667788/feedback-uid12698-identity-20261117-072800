开发离线软件依赖风险判定器，输入包清单、依赖图和本地漏洞公告，不连接在线漏洞库。

请从空目录实现以下可运行工具。环境为 Windows、Python 3.12、仅CPU；不使用Docker或真实外部服务。除题面明确允许的cryptography外只用标准库。输入样例、模拟组件和测试数据由你在项目内构造，不存在另行提供的附件。

核心要求：
1. 实现题内版本规则major.minor.patch[-pre.N]与区间并交差，先比较major/minor/patch数字三元组；三元组相同时正式版高于预发布版，预发布按N数值排序；别名包必须按明确映射归并，生态和命名空间不同的同名包不能混合。
2. 公告可以表达多个受影响区间、补丁回退再次引入和平台条件；从根项目到漏洞依赖输出最短可达证据，区分存在、不可达、条件未知，不能把所有锁文件条目当生产可达。
3. 对升级方案计算受约束的最小变更集合：每条依赖有允许版本集合，所有选中版本必须满足传递约束且无已知受影响区间；无解时输出不可同时满足的约束子集。候选版本均来自输入的有限集合，最小变更以变更包数量为第一目标，再按包名与版本字典序打破平局；同一包全图只能选择一个版本。

必须覆盖的验收场景：预发布边界、分叉依赖、菱形图、循环依赖、回归版本及不可解升级；用小规模枚举校验优化结果和证据链。

交付源代码、README、样例及自动化测试。提供 python -m solution --input cases.json --output result.json 和 python -m unittest discover -s tests -v 两个入口；cases.json可引用项目内源文件或二进制样例。输入输出schema、错误码及未写明的非安全性细节自行设计并完整说明，不能放宽上述要求。测试必须断言具体结果、状态或证据，不能只打印成功；固定种子可重放。所有操作局限在项目测试目录和本机模拟服务。
